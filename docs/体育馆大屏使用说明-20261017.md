# 体育馆大屏使用说明（1.3.15）

## 1. 适用场景

一块体育馆大屏同时显示最多 8 个三人赛场地窗口；支持 1/2/3/4/8 窗口布局。大屏只读，不能修改比赛数据。

大屏页面：`/display.html`（与计分系统同一服务，不需要单独部署）。

## 2. 首次配对

1. 在体育馆大屏电脑打开 `http://<服务地址>:<端口>/display.html`；
2. 页面显示 6 位配对码，10 分钟内有效；
3. 管理员登录计分系统，在“比赛执行 → 大屏”输入配对码并确认；
4. 大屏自动进入展示；凭据保存在该电脑浏览器中，刷新后自动恢复；
5. 需要更换电脑或重新授权时，在控制台点“撤销/重新配对”。

公共电脑不需要登录管理员账号；大屏凭据只能读取展示状态，不能访问报名、成绩、用户等接口。

控制台权限：赛事管理员可控制全部赛事；编排与成绩人员、大屏操作员只能控制管理员分配给自己的赛事。大屏操作员可配对/撤销/推送/预览，并只读查看业务页面；不能计分、提交、更正、管理账号或维护赛事结构。场地记录员和成绩查看者不能进入大屏控制台。

## 3. 配置窗口

1. 选择布局：1 / 2 / 3 / 4 / 8；
2. 给 8 个窗口手动选择三人赛场次；同一场比赛不能占用两个窗口；
3. 1–4 布局时，勾选要显示的窗口；8 布局固定显示全部；
4. 窗口名称默认取场地名，可修改；
5. 选择画面：比分 / 公告 / 待机；
6. 比分刷新间隔：100–1000ms，默认 500ms；单屏建议 250ms，公告/待机固定 2 秒；
7. 点“推送”后大屏在 1 秒内应用；编辑中不点推送不会上屏；
8. 控制台“预览当前大屏”会在新标签页打开真实大屏页面，显示当前已推送内容，不影响现场大屏；预览页左上角显示“预览模式 · 已推送 vN”，存在未推送修改时提示“未推送的修改不会显示”；
9. 比分刷新间隔必须是 100–1000 的整数；输入非法时输入框旁会即时提示并禁用推送，无需等点击后再由服务端报错。

推送完成后按钮会恢复并显示“已推送 vN”；失败会显示“推送失败：原因”，可修改后重试。

大屏不显示赛事标题栏、页脚、主队/客队标签和队员名；8 窗口校名横排，状态、各局小分与标签保持可读字号（小分标签必要时换行），1/2/3/4/8 窗口大比分按窗口数由大到小排列；1–4 窗口放大显示。控制台设备区显示“在线/离线”和最后确认时间，在线状态每 5 秒自动刷新；重新配对会替换该赛事旧凭据，旧大屏立即回到配对界面。

## 4. 实时比分

- 计分员照常逐分记录；本地保存成功后自动异步同步给大屏；
- 网络失败不阻塞计分，只影响大屏；恢复后自动补发最新快照；
- 30 秒心跳；超过心跳阈值大屏显示“数据暂未同步”；
- 8 个窗口相互独立；旧页面、旧草稿或旧事件序号不能覆盖新比分；
- 正式成绩提交、更正或取消后，大屏以正式成绩为准；直播快照不进入名次、积分或导出。

## 5. 公告与待机

- 公告：填写标题和正文，点“推送”后整屏显示；只显示纯文本，不显示底部“管理员推送”提示；
- 待机：只显示“比赛即将开始”，不显示其它副标题或底部提示；
- 切回比分后立即恢复窗口。

## 6. 断线与恢复

- 大屏连续无法连接时显示“连接中断，正在重连”，恢复后自动拉取最新状态；
- 单个窗口快照过期显示“数据暂未同步”，不把旧比分当作实时；
- 凭据被撤销后大屏回到配对界面；
- 预览无效赛事或参数时，页面提示“赛事不存在或预览参数无效”并提供“返回控制台”，不再只显示连接中断。

## 7. 版本与升级

- 版本 1.3.19，浏览器缓存 `stss-shell-v80`；新增 favicon 与 manifest 图标，加载页面不再出现 favicon 404；
- 升级前自动备份数据库到 `data/backups/`；本功能只新增表，不修改既有业务数据；
- 完成或保存当前输入后刷新页面加载新版，无需重启后端；
- 回退：停止服务，从 `data/backups/` 取升级前快照（文件名形如 `event_<ID>-before-display-v1-*.db`），
  复制回 `data/events/event_<ID>.db`，并使用上一版本文件；不会删除正式成绩。旧版本留在
  `events/` 目录中的 `.before-*.db` 可能已被启动迁移改写，仅作提示保留，不再作为回退依据。

## 8. 安全边界

- 大屏凭据只读、单设备、可撤销，服务端只保存哈希；
- 配对码一次性、10 分钟、限流；
- 配对、撤销、推送写入审计日志；
- 大屏不暴露管理员账号，不在 URL 中放凭据；
- 大屏故障不影响计分、提交、更正、排名与导出。
