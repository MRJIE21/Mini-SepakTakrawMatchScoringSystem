# 名次回退与重算操作流程（A-P1-08 配套说明）

日期：2026-10-23
背景：正式更正会改变小组赛结果，系统会自动把受影响的小组名次与项目名次标为“失效/待重新核对”，学校总分同步归零，直到重新确认。本说明给出操作顺序，避免现场把“总分变 0”误判为数据丢失。
适用：三人赛多小组项目（`由多个小组组成的 round_robin`）。

## 1 触发与现象

对已确认场次提交正式更正并经独立复核确认后：

| 位置 | 现象 |
| --- | --- |
| 成绩页 A 组 | 状态从“名次已确认”回到“待重新确认”，出现“确认小组名次”按钮 |
| 项目名次表 | 原现场确认名次全部变“待确认”，来源列附“成绩变化后小组名次失效，项目名次需重新核对” |
| 学校总分 | 全部学校总分为 0，待确认项计数上升 |
| 页面提示 | “N 项名次待核对/待确认，不计入学校团体总分。若刚完成成绩更正或重新确认小组名次，请按当前小组名次重新生成或手工复核。” |

实测：更正把 A 组主队 2:0 胜改为客队 2:0 胜后，A 组 `needs_reconfirm=true`，4 条现场确认名次全部 `pending`，学校总分 18/14/12/10 → 全部 0。

## 2 操作顺序（多小组项目）

1. **重新确认受影响小组**：成绩页对应小组点“确认小组名次” → 弹窗“确认后写入名次快照…” → “确认名次”。该组恢复“名次已确认”。
2. **重新录入项目名次**：项目名次面板点“手工录入现场确认名次”，按新的小组名次逐项录入 1—N 名（名次来源将记为“现场确认”），保存并确认。
3. **核对学校总分**：回“学校总分”页确认总分已按新名次重算、待确认项归零。
4. **补导出**：如已导出过旧名次/总分，重新导出并作废旧文件。

## 3 已知限制（本次实测）

- “按当前小组名次重新生成名次”按钮在多小组项目下点击后提示：**“仅适用于单组循环项目；多组项目请手工核对”**。即多组项目必须走第 2 步的手工录入，不能一键生成。
  建议：多小组项目隐藏该按钮或改文案为“多组项目需手工核对”，避免现场误以为可以一键恢复（未改代码，待确认）。
- 重算只影响“本项目名次/学校总分”，不会改回已确认的比赛结果；比赛结果以更正后的正式版本为准（`result_version` 已递增）。

## 4 验收记录（可复核）

| 步骤 | 结果 |
| --- | --- |
| 更正前 | 名次 1 中国人民大学 18 分、2 中国政法大学 14、3 北京科技大学 12、4 清华大学 10 |
| 更正并经复核 | A 组 needs_reconfirm；4 条名次 pending；总分全 0 |
| 重新确认 A 组 | confirmed=true、needs_reconfirm=false；A 组第 1 变更为中国政法大学（2 分）、第 2 清华大学（1 分） |
| 手工重新录入 | 名次 1 中国政法大学 18、2 清华大学 14、3 北京科技大学 12、4 中国人民大学 10；来源均“现场确认” |
