# 赛事设置同页整合

根据同页维护基本信息、组别与项目、比赛场地的要求，在上一轮 GitHub 参考和界面改进基础上完成三轮方案优化。

参考 [Badminton Tournament Planner](https://github.com/MFuglsang/badminton_tournament_planner) 在赛事详情内管理赛事资料与分项的组织方式，以及 [EntryDesk](https://github.com/ull0sm/EntryDesk) 保留任务上下文的导航原则。具体同页布局与保存粒度由本系统自行实现。

## 第一轮：将三项设置合并

已有赛事在一个页面中同时显示三项设置，取消切换页面的分区按钮。原三个入口成为页内定位，直接聚焦目标标题；大组别仍与所属项目一起管理。新建赛事继续使用独立向导，避免维护现有赛事与创建另一个赛事混淆。

## 第二轮：组织宽屏和窄屏布局

桌面上基本信息、比赛场地并排展示，组别与项目占满下方宽度；平板和手机依次纵向展示，所有区域保持可见。页面的阅读与键盘访问顺序与布局一致，不通过视觉重排改变表单顺序。

页内定位只滚动与聚焦标题，不重新加载页面、不切换赛事，也不隐藏其他区域。不额外叠加固定导航，避免手机已有导航遮挡表单。场地明确为全赛事共用，比赛时间与场地分配仍在项目工作台处理。

## 第三轮：细化保存和更新范围

仅合并展示会暴露旧实现整页重绘的问题：保存一处可能清空其他区域正在输入的内容。因此进一步调整为局部更新：

- 基本信息单独保存，成功后更新该区域及顶栏赛事名称。
- 比赛场地的新增或删除只更新场地列表，保留其他区域和未提交的新增输入。
- 项目改名只更新对应项目行，新增或删除只修改对应列表项；保留同组其他项目名称、待新增项目和待新增组别的当前输入。
- 切换组别只替换其项目区；仅在即将替换的编辑区确有未提交修改时询问是否放弃。新增组别时若当前项目区有修改，保留当前组的选择。
- URL 保留当前组别；旧设置链接继续打开同一页面并定位对应区域，无效组别回退到实际存在的组别。
- 当前组别被其他管理员删除后，重新读取后台会回到有效组别。保存期间离开设置页，旧请求的响应不会改动新页面地址。

每个保存或添加按钮都提交对应内容，不设置容易让人误解的全局保存按钮。后台保存的结构仍是正式数据来源；编辑中的输入只保留在当前页面控件内，刷新页面后重新读取后台，不使用浏览器草稿恢复。

## 验证

使用独立临时数据库和服务检查三项同时显示、页内定位、跨区域与同组项目输入保留、保存结果、旧链接、组别切换、权限、刷新读取后台，以及桌面、平板和手机的实际布局。实际赛事数据仅进行只读快照核对。

验证结果：

- 专项浏览器回归通过，覆盖三处设置的局部更新、异步响应期间离页、后台删除当前组别后的回退，以及原报名种子和场次队列行为。
- 设置页在 2539、1365、768、390、320 像素宽度下通过检查；实际截图已核对。
- 全局 135 个页面与尺寸组合通过，无脚本错误或整页横向溢出。
- 18 项 JavaScript 单元测试、6 项前端静态检查通过。
- 实际 2 个数据库共 66 张表内容与改动前的只读快照一致。
- 运行中的服务已提供更新后的页面文件，资源版本为 `stss-shell-v40`。本轮无数据库迁移，刷新页面即可使用。
