# 学校报名工作台实施记录

日期：2026-10-06。

已实现重构建议的前三步：选人体验、报名校验统一、学校工作台与原子提交。适用本届赛事、学校当前所属单一组别，由管理员或已分配本赛事的组织者录入。

第二期已补齐学校级 Excel 粘贴、多项目 CSV 导入和服务端共享草稿。仍使用同一套学校报名预览、资格校验与原子提交。

## 使用方式

启动或重启服务后，从左侧“学校报名”选择学校。已有学校默认进入“项目报名”，人员名单、项目报名、核对与提交可随时切换。项目报名列表的“更多 → 学校报名工作台”可直接进入该学校。

1. 在人员名单或项目卡片中新增人员，必要时核对全校同名人员并填写区分信息。
2. 分配各项目人员、项目号码和队长；学校可以明确选择不参加某项目。
3. 跨项目换人时，在原项目移除或退出，再分配到目标项目。这些操作只调整同一份草稿。
4. 预览完整变化、最终名单和资料缺项，然后确认整批提交。

不兼项、每校每个人项目最多一人、三人赛最多六人、学校及组别归属、已知性别、项目号码和队长均在服务端复查。三人赛人数不足三人、队长或性别待补可以先报名，预览会提示缺项。

## 保存、并发与重试

- 工作台中的人员资料和项目调整一起提交；任何一项失败，整批回滚。
- 未出现在变更包中的项目保持原状。退出与不参加必须明确指定；尚未决定不会自动算作报名完成。
- 人员和项目号码分别保存。已有人员、队伍和目标项目报名记录沿用原 ID；跨项目移动保留原项目退出记录。
- 输入自动保存到当前设备，按账号、部署、赛事、学校及组别隔离。点击“保存共享草稿”后，本届赛事管理员、组织者可跨设备继续整理。恢复时核对正式报名基线；双方修改同一条人员或项目时逐条选择，不能静默覆盖。
- 网络中断或服务端异常导致结果待核实时，保留原内容、预览和请求标识。可以刷新后原样重试，已成功的提交会重放结果，不重复写入；核实前不能编辑提交内容。
- 首期并发摘要保守地覆盖当前赛事全部报名、项目配置、赛程和成绩。因此其他学校的修改也可能使预览失效；核对后重新预览即可。
- 已锁定/运行并生成场次的项目，新增、退出、恢复、阵容或种子变更均被阻止；已有成绩或名次引用也受保护。系统不自动解锁或删除引用。身份未变的人员备注和常用号码仍可维护。
- 原有独立档案保存仍是即时保存；项目快捷报名和 CSV 导入保留现有入口。CSV 导入整批回滚，项目批量加入继续允许逐项成功。
- 尚未点击“加入人员草稿”的新增输入也会在本机保存和恢复；提交前需先加入或清空，避免遗漏。旧团体报名未选队长时正确提交空值，允许按规则赛前补齐。

## 实现位置

- `app/registration.py`：新旧入口共用的最终名单校验与变更保护。
- `app/api/school_registration.py`：工作台快照、无写入预览、原子提交、版本核对与幂等重放。
- `app/schema.sql`：学校项目选择表，启动时对现有赛事库补齐结构，保留已有数据和 ID。

- `web/js/athletePicker.js`：快捷个人报名优先展示可报名人员，将不可报名人员折叠，同时保留完整同名核对。

## 第二期：表格导入与共享草稿

进入学校工作台，点击“粘贴 / 导入学校报名表”。可下载包含当前项目、正式人员 ID、号码及队长的本校 CSV 模板，或从 Excel 复制含表头的表格。上传支持 UTF-8（含 BOM）及 GB18030 CSV；不直接读取 `.xlsx` 文件。

1. “项目”或“项目ID”与“运动员”为最低表头要求。同一项目的队员放在多行，队长仅一行填“是”。学校、项目 ID 和运动员 ID 若填写，必须与当前学校及组别一致。
2. **所列项目使用表中的完整名单替换草稿名单，未列项目保持原状。** 不参加或退出须明确填写；模板中的“尚未决定”空行保持原状。常用号码、项目号码、种子、报名备注和区分信息分别处理；非空资料补充档案，空白可选资料保留原值。队长栏全空表示待补队长。
3. 项目留空可以仅整理人员。同名档案需填运动员 ID 明确复用；新增不同人时 ID 留空、“同名新建确认”填是，并填写不同的区分信息。核对范围始终包含全校已有人员。
4. “核对表格”只做临时事务投影并回滚，报告原表行号和整批业务校验错误。全部通过后才能“合入学校草稿”。核对时会同时检查工作台原有调整，支持跨项目一次换人。
5. 合入不保存正式报名；再到学校工作台预览并确认整批提交。尚未合入的表格输入也会自动保存，提交前必须合入或清空，避免遗漏。

共享草稿按赛事业务库、学校、当前组别保存，显示保存人、时间和递增版本。它是赛事工作人员共同整理的草稿，不包含个人账号的结果待核实提交包。

- 保存、清除和正式提交核对共享版本。其他设备更新后返回冲突，保留本机内容；可以展开完整共享名单核对，明确载入共享版本或保留本机版本继续。
- 载入共享版本前保留一份本机备份，可点击“恢复切换前的本机草稿”。正式报名基线过期时，继续使用人员、项目逐条核对；尚未加入的输入和表格缓冲保留。
- 共享保存或清除的响应丢失时，原请求保存在原账号本机，刷新后核实重试。同一请求标识不能用于修改后的内容，重复重试不增加草稿版本。
- 成功正式提交在同一事务内清除已核对的共享草稿，并保留递增版本墓碑；失败不清除草稿。旧设备不能以初始版本重新覆盖。
- 本期没有学校自助账号。记录员、查看员不能访问共享草稿或学校表格导入；管理员和组织者沿用现有赛事访问范围。
