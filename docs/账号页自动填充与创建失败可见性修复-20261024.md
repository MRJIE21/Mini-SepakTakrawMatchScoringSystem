# 账号页自动填充与创建失败可见性补强（2026-10-24 · 第三批）

> 背景：第二批修复后，账号页已能在筛选生效时显示“显示 X / 共 N 个账号 · 2 个启用”和“清除筛选”，
> 但现场复核仍出现“共 2 个账号、列表只有 admin、搜索框里仍有 admin”的截图，且服务端日志显示两次
> `POST /api/users` 都返回 409（用户名已存在）。
> 本轮针对剩余的真实成因做补强，不改数据库结构，不改变既有权限与业务口径。

## 1. 剩余成因（已核实）

1. **浏览器/密码管理器自动填充污染筛选与新建表单**：账号页同时存在密码输入框（修改我的密码、初始密码）。
   已保存的凭据会在页面渲染后被自动填入——用户名可能落进账号列表的搜索框（同截图的“当前密码”有掩码点即
   自动填充证据），列表因此被意外过滤成只剩 admin；同样可能把旧凭据填进“新增账号”表单，用户点击创建后
   得到 409 “用户名已存在”，看起来像“新建角色失败/消失”。此前仅设置 `autocomplete` 无法完全阻止该行为。
2. **创建失败反馈不够显眼**：409 只在表单内的一行红字提示；若滚动位置或截图不覆盖该行，用户无法区分
   “创建失败（用户名重复）”与“创建成功但列表没更新”。
3. 刷新后若浏览器再次自动填充，仍会把列表过滤回“部分行”。

## 2. 修改内容

| 文件 | 修改 |
| --- | --- |
| `web/js/ui.js` | 新增 `clearUnintendedAutofill(inputs, onChange)`：在首屏 0/150/400/900/1600/2600ms 清理“没有用户操作痕迹”的非空输入值；真实聚焦、点击、按键、粘贴、输入法开始后不再干预；节点已离开文档时跳过 |
| `web/js/views/admin.js` | 账号搜索框接入自动填充清理（清理后重绘列表）；新建账号表单的登录名/显示名称/初始密码同样清理，避免旧凭据被误提交；创建失败增加 toast（`创建账号失败：…`）并聚焦登录名；`duplicate`（用户名已存在）时清空筛选、定位并高亮现有账号，提示“登录名已存在，已清除筛选并定位到现有账号” |
| `web/js/views/schoolRegistration.js` | 学校人员“查找人员”、项目内人员筛选、学校名单搜索接入同一清理逻辑（清理后重绘/刷新可选人员），避免自动填充把人员/学校列表意外过滤 |
| `web/js/views/resultReview.js` | 复核候选“查找”框接入同一清理逻辑（清理后重新加载列表） |
| `web/sw.js` | 外壳缓存 `stss-shell-v96` → `v97` |
| `tests/account_person_visibility.browser.test.mjs` | 新增回归：模拟无聚焦/无按键的自动填充（搜索框+新建表单）必须被清理且列表不被过滤；用户名重复创建时必须显示错误、清空筛选并定位现有账号；人员搜索自动填充清理 |
| 文档 | 本说明 + README/CHANGELOG + 两份使用说明缓存号同步 |

## 3. 验证

- 新增浏览器断言（`account_person_visibility.browser.test.mjs`）：
  - 模拟自动填充搜索框 → 搜索值为空、不显示筛选统计行、账号行完整；
  - 模拟自动填充新建表单 → 三个字段被清理；
  - 重复用户名创建 → 表单错误可见、toast 含“已存在”、筛选被清空且现有账号行定位高亮；
  - 人员搜索自动填充 → 值被清理、列表按未筛选状态展示。
- 全量回归：Python 全量 540 项、浏览器全量 46 套门禁、发布清单 `--check` 均通过（详见修复报告）。
- 说明：真实密码管理器的填充时机由浏览器决定，本实现覆盖“渲染后数秒内、用户尚未操作”的常见时机；
  用户一旦主动操作（聚焦/输入）就不再干预，不影响正常搜索与筛选。
