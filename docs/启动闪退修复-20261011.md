# Windows 启动闪退修复（2026-10-11）

本机监听 `0.0.0.0:8000` 和 `127.0.0.1:8000` 均被 Windows 拒绝，错误为 `WinError 10013`。
8080、8800、18000 均能监听。未查到 8000 的占用或排除端口记录，因此不推断更具体的系统原因。
原启动入口没有捕获启动错误，双击失败后控制台立即关闭。

## 修复

- 未明确指定端口时，默认端口无法监听会依次尝试 8080、8800、18000，并打印实际访问地址。
- `--port` 或 `STSS_PORT` 明确指定的端口保持原约定，失败时不静默改换。
- `run.py` 捕获导入、配置、数据库及监听错误并显示诊断；Windows 交互窗口启动失败时等待回车。
- 新增 `start.cmd`，检查 Python 3.10+、固定项目工作目录，并在失败时保留错误窗口及退出码。
  脚本使用 Windows CRLF 换行；可直接双击启动。
- 切换端口会更换浏览器的存储作用域，旧地址未提交的记录仍需在旧页面保存或导出。

## 验证

- 启动、赛事库隔离、通讯边界回归共 24 项通过，日志：
  [startup-regression.log](../../tmp/startup-fix-20261011/startup-regression.log)。
- 使用原赛事库的只读备份，验证 `run.py` 默认回退、`start.cmd` 默认回退、脚本指定端口启动：
  三者均返回网页 HTTP 200，未登录接口返回 401。
  明确指定被拒绝的 8000 时返回退出码 1 并保留完整错误。
  [启动验证结果](../../tmp/startup-fix-20261011/startup-verification.json)。
- 数据库完整性检查通过，无外键错误。
- Windows 文件关联的隐藏窗口模拟未取得 HTTP 响应；推荐使用已验证启动链的 `start.cmd`。
  文件关联调用的是 Python 3.14.5，旧 `C:\Windows\py.exe` 另有静默退出问题，不能将它认定为双击失败的唯一原因。
