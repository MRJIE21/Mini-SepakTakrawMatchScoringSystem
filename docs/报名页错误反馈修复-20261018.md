# 报名页错误反馈与校验修复（1.3.17 · 2026-10-18）

## 背景

用户报告“报名页面的使用有bug”。服务端日志显示 2026-10-18 23:21:47—49（UTC 15:21）连续 3 次
`POST /api/schools/5/registration-preview` 返回 400，间隔各 1 秒，随后下载了学校报名模板；期间没有
`registration-commit`，也没有写入任何报名。复现确认：学校报名工作台的错误框位于页面顶部，而“预览整批变更”
按钮在页面最底部；在默认的“项目报名”长页滚到底部点击预览时，错误框位于视口上方约 476—615px，
用户看不到任何失败原因，只会看到按钮短暂显示“处理中…”后恢复，因此反复点击。

## 本轮修复

1. **失败可见**：预览/提交失败时，错误框自动滚入视口并获得焦点，同时显示全局 toast 和底部操作区错误摘要；
   `detail.fields` 中的具体人员/字段说明一并展示，不再只显示笼统文案。错误在重新编辑或成功后清除。
2. **预览前拦截可预见的 400**：
   - 常用号码不在 1—20 时不再自动写入“本项目号码”；服务端 `normalize_members` 也不再使用非法常用号码回填，
     修复“清空项目号码后仍被隐藏回填、之后任何名单调整都报 400”的问题；合法 1—20 仍按原规则预填。
   - 已报名运动员在人员名单中被改成与项目不符的性别时，行内立即提示，预览前阻止并指到具体人员和项目。
   - 个人赛选择“参加报名”但未选运动员、种子序号非正整数、人员姓名为空时，预览前给出明确提示，不发送无效请求。
3. **基线冲突保留输入**：其他入口更新报名导致 409 `registration_stale` 时，使用 `reconcile` 合并后台最新名单，
   保留未冲突的本地人员/项目修改并列出冲突数量，不再静默清空全部未提交内容。
4. 版本 1.3.17、浏览器缓存 `stss-shell-v78`；无数据库结构变更、无新增运行依赖。

## 未纳入本轮（已知边界）

本轮按需求范围只处理反馈与可预见的 400。审查中还发现以下问题，未在 1.3.17 修改，建议后续单独开轮：
同名新人员改名后仍沿用旧的同名核对快照、局域网 HTTP 下 `crypto.randomUUID` 不可用、
待核实提交状态在某些 4xx 后未复位、仅填写部分新增人员输入时表单折叠不可见、
将新人员从“不参加/退出”项目移除后可能残留引用、导入弹窗打开时固定了提交基线。

## 验证

- Node 单元：号码带入、错误摘要、预览前拦截与 409 合并纯函数。
- Python 单元：`normalize_members` 非法常用号码不回填、合法号码仍回填、显式非法项目号码仍按原规则拒绝。
- Playwright：1280 与 390 视口下滚到底部触发服务端 400，断言错误框可见/聚焦、toast 与底部摘要同步；
  预览前拦截不发送请求；合法号码可正常进入核对页。
- 登记回归：既有学校报名 Python/Node/浏览器套件与版本清单测试通过。

## 回退

本轮只修改静态前端、报名成员号码规范化的一个服务端分支与文档/清单。回退时停止服务、替换回 1.3.16 文件并刷新
浏览器（清缓存或 Ctrl+F5）即可；没有数据迁移需要回滚。
