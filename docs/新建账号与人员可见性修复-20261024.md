# 新建账号与人员可见性修复（2026-10-24）

> 对应报障：“新建角色后不能及时更新、刷新后显示异常且新建人物消失”。
> 范围：账号（角色）与学校报名人员（人物）的新建/编辑/列表刷新/页面重载/缓存失效/持久化链路，以及全局同类风险检查。
> 版本：1.5.0（本批只改前端与少量只读接口字段，无数据库结构变更）；外壳缓存 `stss-shell-v94` → `stss-shell-v95`。

## 1. 问题复现与根因

### 1.1 账号管理（#/users）

复现（真实浏览器）：先在“搜索账号”输入 `admin`（或选择任一与新建账号不匹配的角色/状态筛选）→ 新建账号 → 账号已创建成功，但列表仍只显示被筛选的行；页头徽标显示“共 2 个账号 · 2 个启用”而表格只有 1 行。清空筛选或刷新后才看得到新账号，用户看到的就是“新建的角色没更新/消失了”。

根因（均为客户端可见性问题，后台数据完整）：

1. **筛选把新建项隐藏且无任何提示**：`web/js/views/admin.js` 的 `draw()` 先按搜索/角色/状态过滤，再渲染表格；徽标只统计总数，两者口径不一致。浏览器在刷新后会由密码管理器把已保存用户名自动填进无 `autocomplete` 的搜索框，于是每次刷新都重复出现“看不到新账号”。
2. **创建成功后表单状态未复位**：只清空登录名/显示名/初始密码，不清“角色”下拉与“所属赛事”多选，导致下一个账号静默继承上一个账号的角色与赛事访问范围（`eventScopeFields` 没有 reset）。
3. **列表加载无请求序号**：先发出、后返回的旧 `/api/users` 响应可能覆盖新建后的新列表（弱网下出现“需要再操作一次才更新”）。
4. **所属赛事列依赖启动快照**：列内容用 `state.events` 映射事件名，跨标签页/多管理员时可能与后台不一致。

### 1.2 学校报名人员（新增人员）

复现：在“查找人员”输入不匹配的关键字（或把“分配状态”选为“已分配”）→ 新增人员 → 该人员只出现在“本次新增 N 位”的汇总里，人员列表不可见（“新建的人物消失”）；且未提交的修改只保存在本页内存，刷新即丢失。

根因：

1. 新增成功后直接 `draw()`，沿用原筛选值，未复位筛选、未展开/定位新人员。
2. 提交结果“待核实”的恢复包在遇到确定性 4xx（如 409 registration_stale、400 校验失败）时**永不释放**：页面持续显示“待核实”、编辑被禁用，刷新后仍未提交的新增人员从列表中消失，形成无法自救的死锁。
3. 待核实包的存储作用域缺少赛事 UUID（调用方传 `uuid`，读取方用 `event_uuid`），多赛事会共用同一恢复包并串场。

## 2. 修改内容

| 文件 | 修改 |
| --- | --- |
| `web/js/views/admin.js` | 搜索框显式 `autocomplete=off`；有筛选时在列表头显示“显示 X / 共 N 个账号 · M 个启用”并提供“清除筛选”；空结果提供“清除筛选显示全部账号”；新建成功后清空筛选、定位并高亮新账号（`tr.flash`）、完整重置角色与所属赛事；`load()` 增加请求序号，只采纳最后一次响应；所属赛事列优先使用服务端 `event_names`；状态列显示“快照同步中/失败”；“角色与赛事”保存后给出回执提示 |
| `web/js/views/schoolRegistration.js` | 新增人员后 `focusPerson(key, {force:true})`：清空“查找人员/分配状态”筛选、展开并滚动定位新人员；空结果提供“清除筛选显示全部人员”；提交成功重新读取后台名单后复位人员筛选；新增“未提交修改刷新会丢失”常驻提示；修复“待核实”恢复包在确定性 4xx 后的释放逻辑，刷新后可继续编辑与重新预览 |
| `web/js/main.js` | 新外壳接管时显示“系统已更新，刷新页面后使用新版”提示条（不静默刷新，避免打断记录）；待核实请求作用域补赛事 UUID；本机存储写入统一兜底（写满/禁用不阻断启动） |
| `web/js/pendingRequests.js` | 作用域兼容 `event_uuid` / `uuid`，避免退化为 `unidentified` 导致跨赛事共用恢复包 |
| `web/js/ui.js` | 文本输入默认 `autocomplete=off`（密码类字段仍由调用方显式声明 `current-password`/`new-password`）；`promptDialog` 的密码框声明 `new-password` |
| `web/css/app.css` | 新增更新提示条、筛选状态行、未提交提示行样式 |
| `app/api/admin.py` | `/api/users` 增加只读字段 `event_names`；`PUT /api/users/:id` 阻止停用或降级最后一个启用中的管理员（code=`last_admin`） |
| `run.py` | `--set-admin-password` 离线恢复时同时恢复 `role='admin'` 与 `active=1`，避免改密后仍无法登录 |
| `web/sw.js` | 外壳缓存 `stss-shell-v94` → `v95`（缓存优先策略下必须升版本才能让已安装客户端拿到本批修复） |

## 4. 全局同类风险检查结论

已修复（本轮）：账号/人员“新建后被筛选隐藏”、创建后状态未复位、列表加载竞态、待核实恢复包死锁与跨赛事串场、旧外壳导致“刷新还是旧版”、账号页自动填充、最后一名管理员可被停用/降级。

仅报告、未在本轮修改（详见修复报告）：事件作用域请求缺 `X-Event-ID` 时静默落到索引库（服务端契约变更，需先补回归夹具）；赛程新增比赛后被状态/场地筛选隐藏；未提交报名修改无本机草稿恢复（产品取舍：名单以整批提交为准）；`catalog.js` 死代码；本机存储键长期增长未清理；跨标签页 `state.events/structure` 仅启动时加载。
