# 安全加固与运维说明（1.3.16）

本版本在 1.3.15 的基础上完成 P2-B 安全、运维与健壮性加固。以下为现场运维需要知道的行为变化、命令与边界。

## 1. 浏览器安全响应头与 CORS

- 默认只允许同源访问：不再返回 `Access-Control-Allow-Origin: *`。
- 所有响应（页面、静态资源、API、401/403/404、下载、预检）统一带：
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Content-Security-Policy: frame-ancestors 'none'`
  - `Referrer-Policy: same-origin`
- 如需跨源部署（例如前端由其它域名提供），用逗号白名单显式放行：
  `STSS_CORS_ORIGINS=https://score.example.com,http://192.168.1.20:8080`
- 反向代理使用 HTTPS、浏览器地址与后端 Host 不一致时，设置 `STSS_PUBLIC_ORIGIN=https://score.example.com` 以识别同源。
- 未命中白名单的跨源请求返回 403（JSON `cors_forbidden`），预检同样拒绝；同源页面与无 Origin 的脚本/工具请求不受影响。

## 2. 会话与令牌

- 登录令牌在数据库中只保存 `sha256` 哈希，明文只出现在登录响应与浏览器 localStorage。
- 升级到 1.3.16 时自动把旧明文令牌原地替换为哈希，**现有登录会话继续有效，无需重新登录**；迁移幂等。
- 修改自己的密码：当前设备会话保留，该账号其它设备立即失效（页面提示“其他 N 个设备已下线”）。
- 管理员重置口令：该账号全部设备失效。
- 账号页“修改我的密码”区域新增“退出所有设备”，会吊销本人全部令牌并返回数量。
- 任何请求返回 401 时，页面统一回到登录页并提示“登录状态已失效，请重新登录”，不会停在错误页或循环请求。
- **旧备份提醒**：1.3.16 之前生成的备份可能包含明文令牌，请按敏感数据保管并定期轮换；1.3.16 起的新备份只包含哈希与口令哈希（口令仍为 PBKDF2）。

## 3. 审计

- 新增审计动作：`logout`、`logout_all`、`delete_athlete`、`delete_team`、`delete_venue`、`delete_placement`、`clear_school_tiebreak`、`bulk_schedule`、`maintenance_cleanup`、`restore`。
- 审计页新增“范围：赛事 / 账号”切换：登录、登出、失败登录、口令重置等记录在账号（索引库）范围，赛事操作在赛事范围。
- 审计详情不写口令、令牌或 Authorization 头。

## 4. 单实例、端口与日志

- 同一数据目录只允许一个服务进程：启动时在 `data/stss.instance.lock` 获取 OS 级锁并写入 PID/端口/启动时间；第二次启动会明确提示占用实例 PID/端口并以非零码退出，不再静默换端口起第二个实例。
- 端口被占用时直接报错并提示 `netstat -ano | findstr :端口` 与 `--port` 用法，不再自动回退到 8080/8800/18000。
- 进程崩溃后锁由操作系统自动释放；如遇提示锁被占用但无进程，可确认后删除锁文件。
- 日志落盘：`data/logs/server.log`，按大小轮转并保留多份（默认 5MB×5），同时输出到控制台；日志目录不可写时回退控制台，不阻断启动。
- 环境变量：`STSS_LOG_DIR`、`STSS_LOG_LEVEL`、`STSS_LOG_MAX_BYTES`、`STSS_LOG_BACKUP_COUNT`、`STSS_LOCK_FILE`。

## 5. 时间口径（UTC）

- 登录令牌过期、大屏在线/最后确认判定、备份与恢复文件名统一使用 UTC/单调时间；本机时钟回拨不会让已过期令牌复活，也不会影响在线判定。
- 服务器时间字段改为 UTC ISO8601（如 `2026-10-18T14:15:50Z`）。
- 旧数据库中的本地时间字段保留可读并兼容解析，不做批量改写；建议现场电脑启用 NTP 时间同步。

## 6. 数据保留维护（默认关闭）

- 默认运行、启动和日常请求都**不会自动删除**过期令牌、配对码、直播快照或历史请求记录；审计日志默认不清理。
- 手动/计划任务（建议停服执行 apply）：
  - `python run.py maintenance`：默认 dry-run，只输出将清理数量，不写库；
  - `python run.py maintenance --apply`：实际清理并写 `maintenance_cleanup` 审计；
  - `--retention-days N` 覆盖默认保留期（默认 30 天，环境变量 `STSS_RETENTION_DAYS`）。
- 清理范围：过期令牌、过期/已领取配对码、过期直播快照、超过保留期的请求记录；不删除成绩、报名、赛事结构或审计日志。
- apply 需要数据目录锁空闲（服务已停）；dry-run 可在服务运行时执行。

## 7. 备份、恢复与回滚

- 一次性 CLI（详见 `docs/备份恢复与回滚演练-20261018.md`）：
  - `python run.py backup --output <目录>`：对 registry 与全部 `events/event_<数字>.db` 做 SQLite 在线一致快照，生成含 sha256/完整性/关键计数的 `manifest.json`；
  - `python run.py verify --input <目录>`：校验清单哈希、完整性、外键与计数；
  - `python run.py restore --input <目录> --yes`：**要求停服**（锁空闲），先校验、再做恢复前快照、逐文件替换、恢复后自动 verify；清单外旧文件只告警不删除。
- 管理员“下载数据库备份”仍可用；文件名改为 UTC。
- 恢复演练步骤、验收清单与回滚示例见备份恢复文档。

## 8. 其它行为变化

- `/api/events` 的赛事计数改为短 TTL 缓存并在创建/改名/结构变更/赛事写操作后立即失效，接口字段不变。
- 删除场地会返回受影响场次数、递增相关场次的 `schedule_revision/updated_at` 并写审计；已打开的“调整场地时间”弹窗保存时会收到 409 并提示重新读取。
- `/api/matches/bulk-schedule` 支持可选的逐场 `base_schedule_revisions`（当前无前端批量入口），冲突返回 409 `stale_revision` 且不写入。
- 大屏设备令牌独立，不受“退出所有设备”影响；离线标签页在被吊销后再次操作只会显示网络错误，重新联网/刷新后回到登录页。

## 9. 升级与回退

- 升级：替换源码即可；首次启动自动完成 tokens 哈希迁移与 epoch 列增量迁移（不建含明文令牌的备份），刷新浏览器加载 `stss-shell-v77`。
- 回退：切回 1.3.15 文件后启动；新增的 epoch 列与哈希令牌列对旧版本无害（旧版本按 `expires_at` 文本继续工作，但旧版本无法使用 1.3.16 的哈希令牌登录状态，用户需重新登录）。数据本身不需要迁移回退。
