# 账号列表筛选与旧缓存补强（2026-10-24 · 第四批）

> 现场反馈：修复后刷新仍出现“搜索框里有 admin、列表只剩 admin、新建角色 j 已存在但被过滤”，
> 且“打开时列表正常、鼠标点一下就变成筛选态”。本批针对这两个现象做最后补强，不改数据库结构。

## 1. 现象与成因

1. **密码管理器自动填充仍是来源**：Chrome/Edge 保存的登录用户名会在页面渲染后写入“搜索”框。
   若自动填充不触发 `input` 事件（Chrome 凭据填充的常见行为），列表不会立刻过滤——于是出现
   “搜索框显示 admin、列表却是全部账号、没有筛选统计行”；用户点击输入框后浏览器再应用填充并
   触发事件，列表立刻变成“只显示 admin”。这正是“刷新后图一、点一次图二”的表现。
2. **旧外壳缓存放大了问题**：上一版 Service Worker 对 HTML/JS 采用缓存优先，发布后第一次刷新
   仍可能运行旧脚本，导致“修复了但看起来没修好”，也让人无法判断浏览器到底加载了哪一版。
3. 上一轮的定时清理只在首屏约 6 秒内生效，且把 `focus` 当成“用户已操作”的痕迹——自动填充若
   给输入框聚焦，清理会提前停止，值便留在框里。

## 2. 修改内容

| 文件 | 修改 |
| --- | --- |
| `web/js/ui.js` | 新增 `bindFilterInput(input, onChange)`：筛选状态以应用内部值为准；浏览器自动填充的 `insertReplacementText` 事件与静默赋值都不生效并会被纠正；每 0.5 秒核对一次输入框显示值；BFCache 恢复时再次核对。新增 `isAutofillInputEvent()`；`clearUnintendedAutofill` 改为持续轮询、不再把 `focus` 当用户操作，并把真实 `input` 视为用户编辑（失败保留输入等行为不变） |
| `web/js/views/admin.js` | 账号“搜索”改为状态化筛选输入框（自动填充不触发筛选，显示值被纠正）；新建账号表单保留“非用户输入清理（含持续轮询）”；创建失败 toast + 聚焦登录名；用户名重复时清空筛选、定位并高亮现有账号 |
| `web/js/views/schoolRegistration.js` | “查找人员”、项目内人员筛选、学校名单搜索改为状态化筛选输入框 |
| `web/js/views/resultReview.js` | 复核候选“查找”改为状态化筛选输入框 |
| `web/js/main.js` | 导出 `SHELL_VERSION = 'stss-shell-v98'`，侧栏底部显示“版本 1.5.0 · stss-shell-v98”，现场可直接核对浏览器是否加载新版 |
| `web/css/app.css` | 新增 `:-webkit-autofill/:autofill` 动画检测样式（自动填充发生时立即纠正）与侧栏版本行样式 |
| `web/sw.js` | 外壳（HTML/JS/CSS）改为**网络优先、2 秒超时回退缓存**；其余静态资源仍缓存优先。发布后刷新一次即用上新版，断网仍可从缓存打开；缓存版本 `stss-shell-v98` |
| `tests/account_person_visibility.browser.test.mjs` | 新增断言：静默自动填充、点击后 `insertReplacementText` 自动填充都不得过滤列表且需被清理；新建表单自动填充清理；侧栏显示 `stss-shell-v98` |
| 文档 | README/CHANGELOG/两份使用说明的缓存号与说明同步 |

## 3. 验证

- 定向浏览器断言（真实 Edge + 真实服务）：
  - 静默自动填充 `admin` → 0.5 秒内输入框被清空、不显示筛选统计、账号行完整；
  - 点击输入框后浏览器以 `insertReplacementText` 应用填充 → 不触发筛选、值被纠正；
  - 新建账号表单被静默填入旧凭据 → 字段被清理，不会误提交；
  - 侧栏版本行显示 `stss-shell-v98`。
- 全量回归：浏览器 46/46 门禁、Python 540 项、发布清单 `--check`、前端静态护栏均通过（详见修复报告）。
- 旧缓存判断：刷新后看侧栏底部版本；显示 v98 即已加载本批修复。

## 4. 说明

- 自动填充的真实触发时机由浏览器决定；本批覆盖“渲染后任意时刻的静默填充”“点击后填充事件”和
  BFCache 恢复，且不影响用户真实输入（按键/粘贴/输入法/自动化注入均正常筛选）。
- 同名账号创建仍会失败（既有校验）；失败会明确提示并定位现有账号。
