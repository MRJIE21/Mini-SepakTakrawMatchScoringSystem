# 通讯与系统缺陷修复验收

日期：2026-10-11。根据三轮修复方案完成代码、结构迁移及客户端协议更新。所有运行验证均使用独立测试数据库和随机本机端口，真实赛事 `data` 未修改。

## 已完成的修复

| 原审计问题 | 实施结果 |
| --- | --- |
| 1. 小组更正后旧名次、积分继续有效 | 稳定源指纹与独立确认版本；来源失效后撤销自动名次和积分，重新确认时统一重核；保留人工名次 |
| 2. 正式更正覆盖新结果 | 更正、取消必须提交加载时的 base_version 和 request_uid；版本比较、结果、审计及不可变收据在同一事务中完成 |
| 3. 多页覆盖本机得分 | IndexedDB 单事务 CAS，持久 generation 和终态标记；冲突副本保留独立恢复分支，旧回调不能复活草稿 |
| 4. 慢连接积累资源 | 固定工作线程、有界 FIFO、独立过期回收、绝对读写期限；结果物化后先释放数据库连接，再发送响应 |
| 5. 单赛事写锁阻塞全局账号 | 全局账号修改只入持久 outbox；单后台工作线程按单调 revision 重试跨库同步；登录密码计算移出全局写锁 |
| 6. 小监听队列突发拒连 | 生产和全部 HTTP 测试共用 create_server；默认 workers=32、pending=128、backlog=256 |
| 7. 场次关联查询随行数增长 | 按请求批量读取标签、签位来源、比分、归属与审计；普通 100 场页实测 9 次 SELECT |
| 8. 默认列表静默截断 | 显式分页返回 total/has_more/list_revision；legacy 超限返回 pagination_required，权限筛选先于计数和分页 |
| 9. 长请求卡住后续导航 | GET 可取消，计时覆盖响应体；写请求独立于导航；请求冻结账号与赛事身份，旧页面不写回新页面全局状态 |
| 10. 账号跨库同步留下半提交 | 账号变更与持久 outbox 同事务，按目标 revision 合并；异步成功后条件确认，失败可见且重启续传，不同时持有两个库的事务 |
| 11. 名次偏移重核错误 | 快照绝对名次与局部排名使用统一偏移规则，覆盖第 5—6 名与人工并列顺序 |
| 12. 双淘汰旧重置继续生效 | 显式父场次、父结果版本及 active/inactive/review 生命周期；停用或待复核重置不计冠军、不推进签位、不阻塞排程 |

同时修复取消后历史比分误产生冠军、同源小组确认相互覆盖、保存失败重试不恢复按钮、零结果筛选无法清除、旧普通个人输入阻塞新提交、恢复联网与导航竞争导致未捕获取消错误，以及跨账号待核实包完成标记串用。更正业务保存点与外层事务共同保护结果、积分、审计和收据；故障及 COMMIT 失败回滚，原 UID 重放保持原 applied_version。临时 503、超时和导航取消不会使有效账号退出；401 重新登录时清除旧请求作用域，登录容器使用明确 DOM id。

提交协议升级为 `X-Client-Protocol: 2`。客户端发送冻结的 `X-Actor-ID`，服务端核对令牌实际账号；刷新外壳不重新绑定未验证的令牌。旧页面写成绩被明确拒绝；本机库升级到 v2，Service Worker 为 v42。未获得可靠跨页原子存储时保留恢复分支并暂停共享提交。旧页阻塞存储升级时提示先保存/导出并关闭旧页，不绕过升级写另一份数据。

## 验证结果

- Python 完整回归：227 项通过，131.919 秒；[最终原始日志](../../tmp/bug-fix-20261011/python-verified-final.log)。新增结果安全、迁移、跨库恢复、慢连接、事务失败、分页、排程生命周期，以及令牌与冻结账号不一致时拒绝写入的测试。
- 前端规则与真实 Edge 浏览器完整回归：26 个测试文件通过；[最终汇总](../../tmp/bug-fix-20261011/js-actor-verified-status.log)。随后针对登录恢复边界再次运行完整计分交互，17 个场景通过；[新增会话恢复回归](../../tmp/bug-fix-20261011/browser-session-recovery-final3.log)。覆盖本机保存失败、原包重试、离线刷新、提交成功但响应丢失、正式更正、非法输入、权限，以及503保留登录/401重新登录后的真实赛事读取。
- 真实双标签页：同 revision 仅一份 canonical 写入成功，另一份保留分支；晚收据使新 generation 只读但保留；v41 阻塞升级时不写降级副本；无 IndexedDB/Web Locks 时不提交共享草稿。旧普通输入替换时原子归档，旧写入及未知包均不能覆盖新包。
- 结果故障注入：审计/收据插入失败、COMMIT 失败、外层捕获异常、并发相同版本与 UID、取消保留历史、归属变更后原收据查询、重置历史显式复核。
- 跨库故障注入：赛事锁忙时账号和登录不等待赛事；旧 active 快照和旧 ack 不覆盖新停用版本；同步提交后 ack 失败可安全重放；库缺失或身份错误明确可见；停止后可续传。
- 资源边界：100 并发轻请求；滴流不能延长绝对期限；慢读者写超时释放资源。按产品默认容量再验证 32 个滴流 body 占满工作线程时，128 个排队连接仍独立过期；压力解除后 `/api/me` 恢复 200，关闭服务后仅剩主线程。

### 一万场隔离赛事的通信压测

同一台 Windows 机器、回环网络、40 队/120 名队员/10000 场自定义比赛。并发列表示同一批并行请求数，不能换算为现场设备容量。

| 请求 | 并发 / 总请求 | 成功 | P95 | 返回大小 |
| --- | --- | --- | --- | --- |
| 当前用户 | 100 / 200 | 200/200 | 406.67 ms | 275 B |
| 场次分页，100 场 | 30 / 60 | 60/60 | 714.28 ms | 约 120 KB |
| 记录队列，100 场 | 30 / 60 | 60/60 | 677.92 ms | 约 120 KB |
| 方案元数据，不含全量场次 | 30 / 60 | 60/60 | 282.98 ms | 2743 B |
| 登录 | 100 / 100 | 100/100 | 369.23 ms | 194 B |

两种 100 场页均为 11 条 SQL（含事务），其中 9 次 SELECT。原审计的全量/500 场返回与本次分页返回契约不同，延迟不能作为相同负载的直接倍数对比。1000 场夹具也已验证通过。

100 并发独立计分包：54 包首次成功，46 包首次返回受控 503 忙锁；累计 50 次 503。坚持原 UID/原内容重试后 100 包全部成功，数据库恰好 100 份提交，无超过一次的结果版本，完整性与外键检查通过。SQLite 写入仍串行；高峰写入允许有界忙锁重试，不承诺所有写包首次成功。

30 分钟混合运行实测 1800.39 秒、8190 个请求全部 200、零错误。600 份计分与 60 份更正恰好各落库一次，完整性为 ok，外键错误为 0，关闭后仅剩主线程。混合请求 P95 为 164.64 ms；工作线程数保持有界。读分页/元数据、真实逐分成绩、原 UID 重放、正式更正与收据、慢头连接和周期账号更新的采样见 [完整长测证据](../../tmp/bug-fix-20261011/mixed-soak-result.json)。

## 升级与历史数据

1. 旧记录页先保存或导出；停止真实写入，备份全局 registry 和全部赛事库。
2. 重启更新后的后端；赛事结构迁移按原路径自动执行且可重复。没有确认源依据的旧小组快照转为待复核，自动名次和积分暂失效；人工名次、比赛 ID、历史比分和逐分过程保留。旧重置不能唯一证明父关系或已有历史时进入 review，不自动作为冠军来源。
3. 关闭仍占用旧本机数据库的页面，再加载新页面。恢复原账号处理待核实包，以原 UID 查收据或重试；成功收据匹配后才完成本机归档。不要清空浏览器存储解决升级阻塞。
4. 核对历史小组排名、重置赛及自动名次；需要复核的项目重新确认后再计入学校积分。账号 outbox 状态在账号列表中可见。

本轮完成源码修复和隔离验收，未重启现场服务或修改真实赛事库。上线前的实际数据备份、升级及历史人工复核仍须在部署时执行。回退涉及已迁移数据时应使用备份恢复，不能直接运行不兼容旧程序。

大规模验证覆盖本机通信、浏览器交互与数据库边界；无线网络、低配置手机和更长时间运行仍需要现场测量。更高的持续并行写吞吐需要另行评估存储架构，不能仅增加线程或 busy_timeout。
