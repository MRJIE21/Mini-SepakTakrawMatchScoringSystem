# 1.4.0 独立复核工作台升级说明

本说明描述 1.4.0 重构内容，实际验证范围以本轮交付报告和测试日志为准。正式服务切换须单独安排。

## 报名与现场记录

学校人员和项目报名使用统一编辑页，保留个人赛、三人赛的不同阵容规则。人员常用号码与项目号码分别保存，整批核对后提交。

管理首页进入计分任务，可直接查看待复核候选、本机原包和项目进度。记录员仍进入现场任务，成绩查看者与大屏操作员保留各自首页。

## 成绩复核

提交成功表示候选已接收，正式成绩在独立复核批准后生效。管理员须显式授予赛事或项目复核能力；参与过内容录入或转交的人不得审核该内容，管理员同样遵守。

退回和撤回保留原件。修订形成新候选，复核页只读核对，不能直接改分。个人赛原始结果确认与全项目名次确认分别操作；待补全结果不能正式确认。

更正、取消和历史重置赛处置也需要独立复核。提交更正后保留最后正式版本；已领取或有历史的下游须明确核对保留、取消或停用，原过程与审计继续保留。

## 直播与恢复

大屏区分直播、待复核、过期快照和正式成绩；隐藏窗口的数据不发送给配对设备。直播只用于展示，不参与正式排名。旧流、旧归属和旧事件序号不能覆盖当前流。

本机未决请求按原内容、原UID核实，不能因升级、超时或404自动换包。不要清除浏览器数据解决提交问题。服务器备份不包含浏览器尚未上传的原包，应按账号和赛事另行导出。

## 升级与回退条件

继续使用 Python 标准库、SQLite 和原生 JavaScript，无新增运行依赖。缓存版本为 stss-shell-v81。

新数据库增加候选、复核授权、决定、回执和历史记录；历史结果不伪造独立复核人。旧写接口拒绝新确认，原有已保存旧UID仍可查询回执。旧程序缺少新写入版本能力时，成绩写入会被拒绝。

正式冻结、迁移、服务切换及账号授权须单独安排。切换后若已有新候选、决定或授权变更，不能直接恢复不含这些事实的旧备份；恢复程序先保全当前备份并核对全部新事实，缺失时拒绝恢复。优先前向修复，或核对包含全部增量的恢复归档。

含复核事实的恢复还会核对全局账号、角色、赛事权限、撤销令牌和时钟高水位，避免重新启用已撤销的访问能力。恢复归档必须同时保全这些权限状态；不能只拷贝赛事库覆盖当前登记库。

源码清单覆盖产品源码、测试和说明；发布清单绑定源码清单摘要并列出交付文件摘要。发布清单不反向进入源码清单，避免摘要自引用。两份清单须一起验证。
