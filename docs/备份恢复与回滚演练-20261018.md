# 备份、校验、恢复与回滚演练（P2-B · 1.3.16 · 2026-10-18）

本文是现场运维的**可执行步骤单**：如何为一套藤球计分系统数据做一致备份、如何校验
备份是否完好、如何在事故后恢复，以及恢复失败/恢复后发现异常时如何回滚。
所有命令都在产品目录（含 `run.py` 的 `NEW-PROJIECT` 目录）下执行；Windows 请用
`cmd`/PowerShell 打开该目录。

> 安全边界：备份/校验/恢复/维护只针对当前数据目录。真实赛事数据在生产目录，
> 任何演练请先在隔离目录（设置 `STSS_DATA_DIR` 等环境变量）完成一遍。

## 1. 数据构成

| 路径 | 内容 | 是否在成套备份内 |
| --- | --- | --- |
| `<DATA_DIR>/registry.db` | 全局索引库：账号、令牌哈希、赛事索引、大屏设备/配对码 | 是（必须） |
| `<DATA_DIR>/events/event_<数字>.db` | 每届赛事独立业务库（成绩、报名、赛程等） | 是（全部 canonical 赛事库） |
| `<DATA_DIR>/backups/` | 备份归档（`backup-<UTC 时间戳>/`、`pre-restore-<UTC 时间戳>/`） | 否 |
| `<DATA_DIR>/logs/server.log*` | 服务日志（按大小轮转） | 否 |
| `<DATA_DIR>/stss.instance.lock` | 单实例锁（JSON 提示 PID/端口，不含业务数据） | 否 |
| `events/` 内的非 `event_<数字>.db` 文件 | 旧迁移快照/临时文件，启动时跳过 | 否 |

备份使用 SQLite 在线 backup API，**服务运行中也可以备份**，得到的是事务一致的快照；
但 `restore` 与 `maintenance --apply` 必须停服（实例锁空闲）。

## 2. 备份：`python run.py backup`

```bat
python run.py backup
python run.py backup --output D:\stss-backups\现场赛-20261018
```

- 不带 `--output` 时写入 `<DATA_DIR>/backups/backup-<UTC 时间戳>/`；目录同名冲突时
  自动追加 `-2`、`-3` 后缀。
- 输出目录必须不存在或为空；**禁止**把备份目录放进 `events/`（会被启动扫描误判）。
- 备份目录内容：

```text
backup-20261018-141530/
  registry.db
  events/event_1.db
  events/event_2.db
  manifest.json
```

`manifest.json` 记录：备份格式版本、UTC 创建时间、源路径、deployment_id，以及每个
数据库的 `sha256`、字节数、`integrity_check` 结果、外键检查结果、关键表行数、表集合、
`PRAGMA user_version`。

退出码：`0` 成功；`1` 失败（消息在 stderr，常见原因：registry 不存在、输出目录非空、
源库损坏）。

> 令牌安全：1.3.16 起 tokens 只存 sha256 哈希，新备份不含明文令牌；升级前生成的
> 旧备份可能仍含明文令牌，应按敏感数据保管并在升级完成后轮换/删除旧备份。

## 3. 校验：`python run.py verify --input 备份目录`

```bat
python run.py verify --input D:\stss-backups\现场赛-20261018
```

校验内容（任一项不通过即非零退出并明确报错）：

1. `manifest.json` 存在、可解析、版本受支持；
2. 清单内每个文件存在，字节数与 sha256 与清单一致（能发现篡改/拷贝损坏）；
3. 每个数据库 `PRAGMA integrity_check` 为 `ok`；
4. `PRAGMA foreign_key_check` 无违规行；
5. 关键表集合、行数与 `PRAGMA user_version` 与清单一致；
6. `registry.db` 必须且只能有一个，`deployment_id` 与清单一致。

清单外文件只提示、不影响校验结论。退出码：`0` 通过；`1` 不通过。

**建议节奏**：每次备份后立刻 `verify`；重要比赛日开场前、结束后各做一次
“备份 + 校验”；把备份复制到另一块磁盘/移动硬盘。

## 4. 恢复：`python run.py restore --input 备份目录 --yes`

恢复会覆盖当前数据目录中的数据库文件，因此必须显式加 `--yes`，且要求服务已停止。

### 4.1 标准演练/恢复步骤

1. **停止服务**：启动窗口按 `Ctrl+C`，或用任务管理器结束对应进程；确认
   `netstat -ano | findstr :8000` 无监听（端口按实际启动参数）。
2. **确认实例锁空闲**（可选人工核对）：锁文件 `<DATA_DIR>/stss.instance.lock` 的
   内容只是提示；恢复命令会尝试获取实例锁，服务未停会被拒绝并打印占用 PID/端口。
3. **先校验归档**（也可跳过，restore 内部会先 verify，失败不碰数据）：
   `python run.py verify --input 备份目录`
4. **执行恢复**：
   ```bat
   python run.py restore --input D:\stss-backups\现场赛-20261018 --yes
   ```
   恢复命令依次做：获取实例锁 → verify 清单 → 对当前库做 **pre-restore 成套快照**
   （`<DATA_DIR>/backups/pre-restore-<UTC 时间戳>/`）→ 逐文件“临时名 + 原子替换”，
   替换前删除旧库 `-wal/-shm` → 恢复后自动对照清单再次 verify（哈希/完整性/外键/计数）。
5. **启动服务并核对**：`python run.py`；登录后核对赛事列表、学校/报名、赛程、成绩、
   名次与学校总分。恢复后首次启动会执行数据库迁移，属正常。
6. **保留 pre-restore 快照**至少一个比赛周期，确认无异常后再清理。

退出码：`0` 成功；`1` 失败（校验不通过、锁被占用、恢复中断）；`2` 缺少 `--yes`。

### 4.2 恢复失败/恢复后发现异常 → 回滚

恢复命令会打印“恢复前快照（回滚用）”路径，请记下。

```bat
python run.py restore --input <DATA_DIR>\backups\pre-restore-20261018-141812 --yes
```

回滚同样是“停服 → restore → 重启核对”。如果恢复过程被强制中断（断电/杀进程），
数据可能处于部分恢复状态：**不要继续启动服务写数据**，先用 pre-restore 快照回滚，
再重新执行正常的 restore 流程；必要时把 `events/` 与 `registry.db` 整体拷贝出来留证。

### 4.3 常见失败与处理

| 报错/现象 | 处理 |
| --- | --- |
| `恢复被拒绝：同一数据目录已有服务实例正在运行（PID…端口…）` | 先停服；如确认进程已退出仍报错，删除 `<DATA_DIR>/stss.instance.lock` 后重试 |
| `校验失败：备份文件哈希不匹配` / `文件缺失` | 归档已损坏，换另一份备份；不要把该归档恢复到生产目录 |
| `备份数据库外键检查失败` | 归档数据内部引用不一致，换备份；若必须使用，先人工评估 |
| `恢复中断：… 恢复前快照：…` | 用打印的 pre-restore 快照回滚后重试 |
| 恢复后启动报“赛事数据库损坏” | 用 pre-restore 快照回滚；核对备份是否来自同一 deployment_id |
| 磁盘空间不足 | 恢复需要“归档 + 当前数据 + pre-restore 快照”三份空间，至少预留 3 倍数据大小 |

## 5. 数据保留维护：`python run.py maintenance`

默认 **dry-run 只看不删**；删除需显式 `--apply` 且要求停服。清理范围仅限：

- 过期 `tokens`（优先 `expires_at_epoch`，旧行兼容解析本地时间文本）；
- 过期或已领取的 `display_pair_codes`；
- 过期 `display_live`（大屏实时快照，不是正式成绩）；
- 超过保留期的 `request_log`（默认 `STSS_RETENTION_DAYS=30` 天，可用
  `--retention-days N` 覆盖）。

```bat
python run.py maintenance
python run.py maintenance --retention-days 30
python run.py maintenance --apply --retention-days 30
```

- dry-run 可在服务运行时执行，只统计不写库；`--apply` 需停服，结束后在 registry 的
  `audit_logs` 写一条 `maintenance_cleanup` 审计（记录每个库各项数量）。
- **绝不删除**：成绩、报名、赛事结构、大屏设备、审计日志本身。
- 建议在比赛淡季用计划任务定期执行 `--apply`（先停服，或维护窗口内执行）。

## 6. 验收清单（每次重要备份/恢复演练逐项打勾）

- [ ] 备份输出目录与 `manifest.json` 已生成，文件数量与预期一致；
- [ ] `python run.py verify --input <归档>` 退出码 0；
- [ ] 服务运行中执行 `backup` 时提示“检测到运行中的服务实例”，备份仍成功且可 verify；
- [ ] 停服后 `restore --yes` 成功，输出包含“恢复后校验通过”和 pre-restore 快照路径；
- [ ] 恢复前后关键表计数（users/events/schools/teams/participations/matches/
      placements/school_points/individual_results/submissions/tokens 等）与预期一致；
- [ ] 恢复后 `events/` 无 `-wal/-shm` 边车残留；
- [ ] 启动服务后页面上的赛事列表、报名、赛程、成绩、名次与备份时点一致；
- [ ] 备份文件搜索不到明文令牌（`tokens` 行均为 64 位 sha256 十六进制）；
- [ ] 维护 dry-run 数量与 `--apply` 后数量一致（apply 前确认服务已停）。

## 7. 环境变量与默认值

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `STSS_DATA_DIR` | `NEW-PROJIECT/data` | 数据根目录 |
| `STSS_DB` | `<DATA_DIR>/registry.db` | 全局索引库 |
| `STSS_EVENTS_DIR` | `<DATA_DIR>/events` | 赛事库目录 |
| `STSS_BACKUPS_DIR` | `<DB 所在目录>/backups` | 默认备份根目录 |
| `STSS_LOCK_FILE` | `<DATA_DIR>/stss.instance.lock` | 实例锁文件 |
| `STSS_LOG_DIR` | `<DATA_DIR>/logs` | 日志目录 |
| `STSS_RETENTION_DAYS` | `30` | `request_log` 保留天数 |
| `STSS_LOG_MAX_BYTES` / `STSS_LOG_BACKUP_COUNT` | `5242880` / `5` | 日志轮转大小/份数 |
